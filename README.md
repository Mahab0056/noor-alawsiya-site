# موقع ومنصة مدرسة نور الأوصياء للدراسات القرآنية

الموقع الحي: https://noor-alawsiya.com (Railway، مشروع `noor-alawsiya-com`، يُنشر من فرع `main`).

## التشغيل محلياً

```bash
npm install
npm run dev
```

```bash
npm run lint
npm run build
```

## البنية

- `app/` الصفحات العامة: الرئيسية `/`، سجل الدورات والأساتذة `/courses`، سياسة الخصوصية `/privacy`.
- `app/register`، `app/login`، `app/account`: تسجيل الطالب (ثلاث خطوات مع الاستبيان)، دخوله، ومتابعة حالة طلبه.
- `app/admin`: لوحة الإدارة. `/admin` طلبات التسجيل (قبول ورفض مع ملاحظة)، `/admin/form` بناء الاستبيان، `/admin/admins` المشرفون والدعوات (للمدير الأعلى)، `/admin/invite/<رمز>` قبول الدعوة، `/admin/login` الدخول.
- `app/actions.ts` و`app/admin/actions.ts`: إجراءات الخادم. كل إجراء إداري يتحقق من جلسة المدير بنفسه.
- `components/` الترويسة والتذييل، بطاقة الدورة، نماذج التسجيل والدخول، هيكل لوحة الإدارة.
- `lib/data.ts` سجل الدورات والأساتذة (من سجل المدرسة بتاريخ 18/11/2026). القيمة `null` تعني أن المعلومة ناقصة في السجل وتُعرض «غير مذكور».
- `lib/db.ts` الاتصال بقاعدة البيانات والترحيلات، `lib/auth.ts` كلمات المرور والجلسات وحدود المحاولات، `lib/email-codes.ts` رمز الدخول بالبريد والأجهزة المحفوظة، `lib/registration.ts` و`lib/admin.ts` و`lib/accounts.ts` منطق التسجيل والإدارة، `lib/session.ts` كوكي الجلسة، `lib/form-rules.ts` القواعد المشتركة بين الخادم والمتصفح.
- `db/migrations/` مخطط قاعدة البيانات. على الجهاز المحلي (PGlite) تُطبَّق الترحيلات تلقائياً عند أول اتصال؛ في الإنتاج (Postgres) تُطبَّق فقط بالأمر `npm run migrate` قبل كل نشر.
- `app/globals.css` نظام التصميم (أصفر `#FFFA00` وأسود)، `app/site.css` إضافات الموقع، `app/portal.css` و`app/forms.css` شاشات التسجيل والإدارة والنماذج.

## قاعدة البيانات

- في الإنتاج: Postgres عبر `DATABASE_URL`، مع `APP_SECRET` (32 حرفاً عشوائياً على الأقل) لمفتاح رموز الدخول، و`APP_ORIGIN` و`RESEND_API_KEY` و`EMAIL_FROM` لبريد الدعوات ورموز الدخول. انظر `.env.example`.
- على جهازك: بلا `DATABASE_URL` يستخدم التطبيق قاعدة PGlite داخل المجلد `.pglite/` (يتجاهله git)، فلا يحتاج خادماً يعمل.

```bash
npm test                      # اختبارات المنطق على قاعدة في الذاكرة
npm run seed                  # الدورات من سجل المدرسة + استبيان ابتدائي من أربعة أسئلة
npm run seed -- --demo        # للتجربة المحلية فقط: طلاب وهميون ومدير تجريبي (بياناتهم في .pglite/demo-credentials.json)
ADMIN_PASSWORD='…' npm run create-admin -- "الاسم" email@example.com super   # محلياً فقط (يطبع سرّاً لتطبيق المصادقة، لا يلزم إلا مع ADMIN_TOTP=1)
```

لا تُدخل بيانات طلاب حقيقية في القاعدة المحلية.

### فحص صلاحيات الـ Server Actions (في CI)

وظيفة `actions-e2e` في `.github/workflows/ci.yml` تبني الموقع، وتشغّل `next start` على Postgres مؤقت ببيانات وهمية (`scripts/e2e/setup.ts`)، ثم تنادي كل Server Action في `app/**/actions.ts` كما يناديها المتصفح (`scripts/e2e/actions-probe.mjs`): مشرف مقابل مدير أعلى، طالب مقابل مشرف، بلا جلسة، من موقع آخر، وحدود المحاولات. لكل action فحص إيجابي يثبت أن الطلب وصل فعلاً، وأي action جديد بلا فحص أو سبب مكتوب يُفشل الوظيفة. لتشغيلها محلياً على قاعدة فارغة مؤقتة (لا تشغّلها على قاعدة حقيقية، فهي تغيّر البيانات):

```bash
npm run build
DATABASE_URL=postgres://…/noor_e2e APP_SECRET=… npm run seed
DATABASE_URL=… APP_SECRET=… npx tsx --conditions=react-server scripts/e2e/setup.ts /tmp/e2e-tokens.json
DATABASE_URL=… APP_SECRET=… npx next start -H 127.0.0.1 -p 3000 &
DATABASE_URL=… node scripts/e2e/actions-probe.mjs http://127.0.0.1:3000 /tmp/e2e-tokens.json
```

## المشرفون والدعوات

- دوران: **مدير أعلى** (`super_admin`) يفعل كل شيء ويدعو المشرفين ويوقفهم من `/admin/admins`، و**مشرف** يراجع الطلبات ويعدّل الاستبيان.
- لا يُنشأ مشرف بكلمة مرور يكتبها غيره: يُرسَل له رابط دعوة بالبريد (Resend)، فيضع اسمه وكلمة مروره فيصبح مفعّلاً. قبل ذلك لا يستطيع الدخول.
- الدخول: البريد وكلمة المرور، ثم على كل جهاز جديد رمز من ستة أرقام يصل بالبريد (مرة واحدة، 10 دقائق، 5 محاولات، 5 رموز في الساعة على الأكثر). «تذكّر هذا الجهاز ٣٠ يوماً» يُغني عن الرمز على ذلك الجهاز، ويُنسى عند الإيقاف أو إعادة الدعوة.
- تطبيق المصادقة (QR) مطفأ بقرار 19/11/2026؛ الكود باقٍ ويعود بالمتغيّر `ADMIN_TOTP=1`.
- الرابط يصلح مرة واحدة ولمدة 48 ساعة، وأي دعوة أحدث تبطله. لا يُخزَّن إلا تجزئة الرمز، وسجل العمليات يذكر رقم المشرف ورقم الدعوة فقط.
- أول مديرَين أعليين يدعوهما المشغّل بعد النشر (على Railway):

```bash
npm run create-admin -- --invite someone@example.com --role super
npm run create-admin -- --invite someone@example.com --role admin
npm run create-admin -- --invite someone@example.com --role super --reset   # مشرف مفعّل نسي كلمة مروره
```

يحتاج `RESEND_API_KEY` و`APP_ORIGIN` (و`EMAIL_FROM` اختيارياً). إن نقص أحدها أو رفض Resend الرسالة يفشل الأمر ولا يُنشئ شيئاً، ولا يطبع الرابط ولا البريد.

### إذا قُفل حساب مشرف

خمس محاولات دخول فاشلة خلال ربع ساعة تقفل الدخول بهذا البريد ربع ساعة (قاعدة المرحلة 2 كما هي). لفكّه قبل ذلك: مدير أعلى آخر يفتح `/admin/admins` ويضغط «فك القفل» بجانبه (يمسح محاولاته الفاشلة الأخيرة؛ حدّ العنوان باقٍ). لهذا يوجد مديران أعليان: لا يبقى الموقع بلا مدير إن قُفل أحدهما. إن نسي مشرف كلمة مروره: «إعادة دعوة» تمسح كلمة مروره وأجهزته المحفوظة وتُنهي جلساته وترسل له رابطاً جديداً. «إيقاف» يُنهي جلساته فوراً ويمنع دخوله.

## الخصوصية والأمان

- الطالب: الاسم، سنة الميلاد فقط، رقم الهاتف، وكلمة مرور تُحفظ مجزّأة (argon2id). من هو دون 18 يحتاج اسم ولي الأمر ورقمه وموافقته، والقاعدة ترفض السجل بدونها.
- المدير: كلمة مرور (12 حرفاً على الأقل) ورمز بالبريد على كل جهاز جديد. لا يُخزَّن الرمز بل HMAC له بمفتاح من `APP_SECRET`، ويُقارن بزمن ثابت. الدخول الفاشل محدود بخمس محاولات للحساب من العنوان نفسه، ومئة للحساب من كل العناوين، وعشرين للعنوان كل ربع ساعة، وفتح الدعوة محدود كذلك.
- الجلسات في كوكي `httpOnly` و`sameSite=lax`، ولا يُحفظ في القاعدة إلا تجزئة الرمز.
- سجل التدقيق يذكر من قبِل أو رفض أي طلب بالرقم المرجعي فقط، بلا أسماء ولا هواتف.

## قواعد المحتوى

- لا تُنشر أسماء الطلاب أو المتخرجين إلا بموافقة المدرسة (وولي الأمر لمن هو دون 18).
- لا تُخترع معلومة ناقصة في سجل المدرسة.

## المراحل

1. الأساس والموقع العام الجديد.
2. التسجيل من الموقع مع الاستبيان ولوحة الطلبات (هذه المرحلة).
3. الدورات والدروس وبوابة الطالب.
4. الامتحانات والنتائج والتصدير.
