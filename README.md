# موقع ومنصة مدرسة نور الأوصياء للدراسات القرآنية

الموقع الحي: https://noor-alawsiya.com (Railway، مشروع `noor-alawsiya-com`، يُنشر من فرع `main`).

## التشغيل محلياً

```bash
npm install
npm run dev
```

```bash
npm run lint
npm run build
```

## البنية

- `app/` الصفحات العامة: الرئيسية `/`، سجل الدورات والأساتذة `/courses`، سياسة الخصوصية `/privacy`.
- `app/register`، `app/login`، `app/account`: تسجيل الطالب (ثلاث خطوات مع الاستبيان)، دخوله، ومتابعة حالة طلبه.
- `app/admin`: لوحة الإدارة. `/admin` طلبات التسجيل (قبول ورفض مع ملاحظة)، `/admin/form` بناء الاستبيان، `/admin/admins` المشرفون والدعوات (للمدير الأعلى)، `/admin/invite/<رمز>` قبول الدعوة، `/admin/login` الدخول.
- `app/actions.ts` و`app/admin/actions.ts`: إجراءات الخادم. كل إجراء إداري يتحقق من جلسة المدير بنفسه.
- `components/` الترويسة والتذييل، بطاقة الدورة، نماذج التسجيل والدخول، هيكل لوحة الإدارة.
- `lib/data.ts` سجل الدورات والأساتذة (من سجل المدرسة بتاريخ 18/11/2026). القيمة `null` تعني أن المعلومة ناقصة في السجل وتُعرض «غير مذكور».
- `lib/db.ts` الاتصال بقاعدة البيانات والترحيلات، `lib/auth.ts` كلمات المرور والجلسات وحدود المحاولات، `lib/email.ts` بريد رمز الدخول، `lib/invites.ts` و`lib/mail.ts` دعوات المشرفين، `lib/registration.ts` و`lib/admin.ts` و`lib/accounts.ts` منطق التسجيل والإدارة، `lib/session.ts` كوكي الجلسة، `lib/form-rules.ts` القواعد المشتركة بين الخادم والمتصفح.
- `db/migrations/` مخطط قاعدة البيانات. على الجهاز المحلي (PGlite) تُطبَّق الترحيلات تلقائياً عند أول اتصال؛ في الإنتاج (Postgres) تُطبَّق فقط بالأمر `npm run migrate` قبل كل نشر.
- `app/globals.css` نظام التصميم (أصفر `#FFFA00` وأسود)، `app/site.css` إضافات الموقع، `app/portal.css` و`app/forms.css` شاشات التسجيل والإدارة والنماذج.

## قاعدة البيانات

- في الإنتاج: Postgres عبر `DATABASE_URL`، مع `APP_SECRET` (32 حرفاً عشوائياً على الأقل) تُشتق منه مفاتيح التطبيق. البريد عبر Resend: `RESEND_API_KEY` و`EMAIL_FROM` من نطاق موثّق عنده، و`APP_ORIGIN` لروابط الدعوات. انظر `.env.example`.
- على جهازك: بلا `DATABASE_URL` يستخدم التطبيق قاعدة PGlite داخل المجلد `.pglite/` (يتجاهله git)، فلا يحتاج خادماً يعمل.

```bash
npm test                      # اختبارات المنطق على قاعدة في الذاكرة
npm run seed                  # الدورات من سجل المدرسة + استبيان ابتدائي من أربعة أسئلة
npm run seed -- --demo        # للتجربة المحلية فقط: طلاب وهميون ومدير تجريبي (بياناتهم في .pglite/demo-credentials.json)
npm run create-admin -- "الاسم" email@example.com super   # محلياً فقط: مشرف مفعّل ببريده وحده
```

على جهازك لا يُرسل بريد فعلي، فاقرأ رمز الدخول من جدول `admin_login_codes`. لا تُدخل بيانات طلاب حقيقية في القاعدة المحلية.

## المشرفون والدعوات

- الدخول كما في الموقع الحي منذ PR #10 (22/11/2026): البريد، ثم رمز من ستة أرقام يصل إليه في كل دخول. لا كلمة مرور ولا تطبيق مصادقة.
- دوران: **مدير أعلى** (`super_admin`) يفعل كل شيء ويدعو المشرفين ويوقفهم من `/admin/admins` ويدير روابط الحملات، و**مشرف** يراجع الطلبات ويعدّل الاستبيان. «المشرف العام» (`owner`) الذي زرعه `0005_owner_admin` صار مديراً أعلى بالترحيل `0013`.
- مشرف جديد: يُرسَل له رابط دعوة بالبريد (Resend)، فيكتب اسمه فيصبح مفعّلاً ويدخل. قبل ذلك لا يصله رمز دخول.
- الرابط يصلح مرة واحدة ولمدة 48 ساعة، وأي دعوة أحدث تبطله. لا يُخزَّن إلا تجزئة الرمز، وسجل العمليات يذكر رقم المشرف ورقم الدعوة فقط.
- يدعو المدير الأعلى من `/admin/admins`، أو المشغّل من سطر الأوامر (على Railway):

```bash
npm run create-admin -- --invite someone@example.com --role super
npm run create-admin -- --invite someone@example.com --role admin
npm run create-admin -- --invite someone@example.com --role super --reset   # مشرف مفعّل يُعاد تفعيله برابط جديد
```

يحتاج `RESEND_API_KEY` و`APP_ORIGIN` و`EMAIL_FROM`. إن نقص أحدها أو رفض Resend الرسالة يفشل الأمر ولا يُنشئ شيئاً، ولا يطبع الرابط ولا البريد.

### إذا قُفل حساب مشرف

خمس محاولات فاشلة لهذا البريد خلال ربع ساعة، من أي عنوان، تقفل الدخول به ربع ساعة (كما في الموقع الحي). لفكّه قبل ذلك: مدير أعلى آخر يفتح `/admin/admins` ويضغط «فك القفل» بجانبه (يمسح محاولاته الفاشلة الأخيرة؛ حدّ العنوان باقٍ). لهذا يُستحسن مديران أعليان. «إعادة دعوة» تُنهي جلسات المشرف ورموزه وترسل له رابطاً جديداً. «إيقاف» يُنهي جلساته فوراً ويمنع دخوله.

## الملخص اليومي للمديرين

رسالة واحدة في اليوم إلى المديرين الأعلين المفعّلين (`owner` و`super_admin` غير الموقوفين، من القاعدة لا من الإعدادات): «٨ طلبات تنتظر، أقدمها منذ ٥ أيام»، وكم طلباً تجاوز ٤٨ ساعة، وعدد المنتظر في كل دورة، ورابط واحد إلى قائمة الطلبات المنتظرة الأقدم أولاً. أرقام وأسماء دورات فقط: لا اسم طالب ولا ولي أمر ولا هاتف ولا عمر ولا ملاحظة. لا تُرسل إن لم ينتظر طلب.

- مرة واحدة في يوم بغداد: الجدول `admin_digest_log` (الترحيل `0016`) يحجز اليوم قبل الإرسال، فالنداء الثاني في اليوم نفسه لا يرسل شيئاً. إن فشل الإرسال لكل المستلمين لا يُحجز اليوم، فيحاول النداء التالي من جديد.
- خلف العلم `ADMIN_DIGEST` (القيمة `1`)، مطفأ افتراضياً: المسار يجيب 404، و`npm run digest` يطبع `off` ويخرج بـ 0 دون أن يفتح القاعدة.
- طريقتان للتشغيل، والمنطق واحد (`lib/admin-digest.ts`):
  - `npm run digest` (الأبسط لخدمة cron على Railway).
  - `POST /api/cron/admin-digest` مع الترويسة `Authorization: Bearer <ADMIN_DIGEST_TOKEN>` (٣٢ حرفاً عشوائياً على الأقل). رمز ناقص أو خطأ = 404 مثل العلم المطفأ.
- يحتاج `DATABASE_URL` و`APP_ORIGIN` و`RESEND_API_KEY` و`EMAIL_FROM`، كرسائل رمز الدخول.

### تشغيله على Railway (لمهاب، ثلاث خطوات)

1. في خدمة الموقع: Variables ← أضف `ADMIN_DIGEST` = `1`. (لا تلزم `ADMIN_DIGEST_TOKEN` إلا إذا أردت استدعاء الرابط من خارج Railway.)
2. أنشئ خدمة جديدة من المستودع نفسه والفرع نفسه (New ← GitHub Repo). في Settings: أمر التشغيل `npm run digest`، وCron Schedule `0 6 * * *` (Railway يحسب بتوقيت UTC، فهذا ٩:٠٠ صباحاً ببغداد). في Variables أضف بالمرجع (Reference) من خدمة الموقع: `DATABASE_URL` و`APP_ORIGIN` و`RESEND_API_KEY` و`EMAIL_FROM`، و`ADMIN_DIGEST` = `1`.
3. للتجربة: من الخدمة الجديدة اضغط «Run now» (أو Deploy). في السجل يظهر `admin-digest: {"status":"sent",...}` وتصل الرسالة إلى بريد المديرين الأعلين. شغّلها ثانية: يظهر `"status":"already"` ولا تصل رسالة ثانية.

للإيقاف: احذف `ADMIN_DIGEST` من الخدمة الجديدة (أو اجعله `0`)، فيطبع الأمر `off` ولا يرسل شيئاً.

## الخصوصية والأمان

- الطالب: الاسم، سنة الميلاد فقط، رقم الهاتف، وكلمة مرور تُحفظ مجزّأة (argon2id). من هو دون 18 يحتاج اسم ولي الأمر ورقمه وموافقته، والقاعدة ترفض السجل بدونها.
- المدير: رمز من ستة أرقام يصل إلى بريده في كل دخول، صالح عشر دقائق ويُستعمل مرة واحدة، ويُخزَّن في القاعدة بـ hmac بمفتاح `APP_SECRET` لا كرقم. طلب الرمز لبريد غير مسجَّل أو معلّق أو موقوف يُجاب بالجواب نفسه ولا يُرسل شيئاً. الدخول الفاشل محدود بخمس محاولات للحساب (من كل العناوين) وعشرين للعنوان كل ربع ساعة، والعدّ ذرّي فلا تتجاوزه طلبات متوازية. فتح الدعوة محدود كذلك.
- الجلسات في كوكي `httpOnly` و`sameSite=lax`، ولا يُحفظ في القاعدة إلا تجزئة الرمز.
- سجل التدقيق يذكر من قبِل أو رفض أي طلب بالرقم المرجعي فقط، بلا أسماء ولا هواتف.

## قواعد المحتوى

- لا تُنشر أسماء الطلاب أو المتخرجين إلا بموافقة المدرسة (وولي الأمر لمن هو دون 18).
- لا تُخترع معلومة ناقصة في سجل المدرسة.
